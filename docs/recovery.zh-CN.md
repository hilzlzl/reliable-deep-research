# 任务恢复

[English](recovery.md) · [架构设计](project_overview.zh-CN.md) · [数值证据](../benchmarks/results/recovery.json)

运行时在 SQLite 中保存任务状态，并将成功任务的结果与完成状态一起提交。使用同一个数据库重新运行同一任务 DAG，会复用已提交结果。显式重放使选定任务及其下游失效。未完成或重放尝试产生的 Evidence 和 Claim 会在重试前失效清理，避免旧记录进入新报告。

## 已有测量

| 合成故障 | 次数 | 成功运行 | 符合预期 |
| --- | ---: | ---: | ---: |
| 短暂异常 | 30 | 30 | 30 |
| 短暂超时 | 30 | 30 | 30 |
| 持续异常 | 30 | 0 | 30 |
| 持续超时 | 30 | 0 | 30 |

持续故障应在重试上限后失败，因此这些场景中的零成功数符合预期。

另一项实验使用 `os._exit` 和新进程，每个场景、每种模式各运行 20 次：

| 场景 | 仓库对照 | 可靠运行时 |
| --- | --- | --- |
| 根任务提交后退出 | 重启成功 20/20；已完成根任务重复执行 20/20 | 重启成功 20/20；根任务在两个进程中总共只执行一次 |
| 写入证据期间、任务提交前退出 | 重启成功 20/20；无证据存储 | 重启成功 20/20；清理后无残留 Evidence/Claim |

这些合成任务验证具体运行语义，不代表生产故障率或付费调用保证。崩溃前发出的请求即使未提交结果也可能计费。预算计数在内存中，不提供跨进程持久化计费约束。一个数据库仅属于一道研究问题。

## 无密钥复现

```bash
uv run --frozen python -m experiments.reliability.reliability_demo
uv run --frozen python -m experiments.reliability.process_recovery_experiment --trials 2 --output artifacts/recovery_smoke
```

进程恢复实验使用新的或空的输出目录。将 `--trials 2` 改为 `--trials 20` 可达到公开测量规模。轻量演示注入异常后重放验证与报告任务；进程实验会主动终止工作进程。
