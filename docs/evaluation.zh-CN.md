# 深度研究与任务恢复评估

[English](evaluation.md) · [中文 README](../README.zh-CN.md)

## 实验设置

比较仓库基础版、早期 Claim-first 方案和 Reliable Deep Research，问题覆盖智能体系统、AI 应用、软件工程与 CAD 生成。

| 项目 | 仓库基础版 | Claim-first | Reliable Deep Research |
| --- | --- | --- | --- |
| 实验规模 | 30 道问题 × 2 次，共 60 次尝试 | 30 道问题 × 2 次，共 60 次尝试 | 60 个统计位置：原 47 次通过 + 13 次重跑[^replacement] |
| 工作方式 | 上游研究流程，关闭新增可靠性、证据审核与修复 | 证据 → 准入 Claim → 报告 | 问题拆解、段落审核、有界补搜与反馈修复 |
| 配置标识 | `baseline` | `reliable_v2` | 发布配置 `coverage_v2`；保留记录来自 `coverage_v1` |

仓库基础版保留了本仓库对检索、模型接入和预算的实验适配，不代表未经修改的官方 Open Deep Research。

三组使用 24 份固定来源，按 1,200 字符切块、重叠 200 字符，通过 BM25 + BGE-small-en-v1.5 融合检索，每次最多返回 5 个片段。模型网关别名为 `gpt-6.1-sol`，低推理强度、流式输出；托管模型的具体实现未独立核实。生成流程只接收问题文本，不接收参考答案。

每次尝试上限为 40 次模型调用、4 次检索、6 次任务尝试、1,200 秒、250,000 个估算输入 token 和 120,000 个观测输出 token；研究并发为 2。历史批次使用 18 个报告进程，重跑批次使用 6 个，耗时受共享 API 负载和配置变化影响。

[^replacement]: 原始 coverage 实验为 47 次通过、11 次降级、2 次失败。全部 13 个未通过位置各重跑一次，得到 12 次通过、1 次失败；保留失败重跑，不挑选最好结果。表中是跨两种配置的开发汇总，实际消耗 73 次生成尝试，尚未用发布配置独立完成全量 60 次新运行。

## 实验结果

| 指标 | 仓库基础版 | Claim-first | Reliable Deep Research[^replacement] |
| --- | ---: | ---: | ---: |
| 验收通过 | 52/60 | 51/60 | **59/60** |
| 降级待复核 | 0 | 0 | **0** |
| 失败或预算耗尽 | 8 | 9 | **1** |
| 全部尝试要点覆盖 | 135/168（80.4%） | 109/168（64.9%） | **149/168（88.7%）** |
| 通过报告条件覆盖 | 135/145（93.1%） | 109/144（75.7%） | **149/165（90.3%）** |
| 抽样引用支持 | 123/202（60.9%） | 244/254（96.1%） | **219/234（93.6%）** |
| 平均耗时（秒，含失败） | 404.9 | 667.6 | **319.3** |
| 平均模型调用（含失败） | 9.52 | 19.42 | **15.25** |
| 平均检索次数（含失败） | 1.95 | 3.72 | 2.50 |
| 观测输出 token 总数 | 517,433 | 1,016,755 | 514,544 |

耗时与用量只统计表中保留的 60 个位置，不包含被替换的原 13 次尝试和外部评审开销；调用与 token 数不是货币成本。完整数值与逐位置映射见[实验记录](../benchmarks/results/README.md)。

## 评分规则

| 指标 | 计算方式 |
| --- | --- |
| 验收通过 | 运行满足各自流程的验收检查；不同方案的验收约定不同，不直接等同于语义质量 |
| 全部尝试要点覆盖 | 通过报告明确覆盖的参考要点数 ÷ 全部 60 个位置的参考要点数；失败和降级计零 |
| 通过报告条件覆盖 | 通过报告明确覆盖的参考要点数 ÷ 这些报告的参考要点总数 |
| 抽样引用支持 | 每份通过报告按稳定哈希抽取最多五条带引用陈述，提供来源片段评审，统计判为支持的比例 |

三份通过的仓库基础版报告没有可提取引用，不进入引用支持分母。`incomplete_evidence` 可以通过可靠性验收但仍有回答缺口；`degraded` 表示需要复核。重复运行嵌套在 30 道问题中，不是 60 道独立问题。

参考要点由助手编写，评审与生成使用相同网关模型别名，尚无独立人工复核；部分问题曾用于开发，因此不是未见测试集。重跑中仅五份报告使用修复后验证，十二份通过报告中仅八份被外部评审认为完全覆盖；不能将验收提升全部归因于内容修复，也不能据此声称普遍优于上游。剩余失败为 `agent_02` 第 2 次重复，超时后重试耗尽研究检索额度。

## 任务恢复实验

恢复能力通过独立的合成任务测试，不混入上面的报告质量统计。

| 场景 | 规模 | 结果 |
| --- | --- | --- |
| 短暂异常、短暂超时 | 各 30 次 | 各 30/30 恢复成功 |
| 持续异常、持续超时 | 各 30 次 | 均在重试上限后失败，符合预期 30/30 |
| 根任务提交后退出进程 | 每种实现各 20 次 | 两种实现均重启成功 20/20；基础对照重复执行根任务，可靠运行时复用结果 |
| 写入证据、任务提交前退出 | 每种实现各 20 次 | 两种实现均重启成功 20/20；基础对照无证据存储，可靠运行时清理后旧 Evidence/Claim 为零 |

这些测试验证任务级结果复用和失效清理，不代表生产故障率。整个 LangGraph 会话位置和预算计数器没有跨进程持久化，崩溃前发出的外部请求仍可能计费。原始数值见[恢复记录](../benchmarks/results/recovery.json)。

## 离线复核

在仓库根目录执行，无需模型密钥；进程恢复实验的输出目录应为新目录或空目录。

```bash
uv run --frozen python -m experiments.evaluation.verify_release_results
uv run --frozen python -m experiments.reliability.process_recovery_experiment --trials 2 --output artifacts/recovery_smoke
```

第一条命令复算结果、检查源文件哈希和全部 13 个替换映射，不能验证语义判定是否正确。第二条将 `--trials 2` 改为 `--trials 20` 即为发布试验规模。问题、来源元数据、环境和实验补充记录见[基准索引（英文）](../benchmarks/README.md)。
