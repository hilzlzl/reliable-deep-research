# 实验评测与发布选择

[English](evaluation.md) · [中文首页](../README.zh-CN.md)

## 发布流程

项目以 **Reliable Deep Research** 发布，采用审核反馈驱动的有界修复流程。Claim-first 是早期评测对照。公开入口启用围绕问题的报告、段落支持检查、有界补搜与复核后的局部修复，不选择旧 Claim-first 流程。

<a id="experiment-identifiers"></a>

## 方案说明

| 方案 | 说明 |
| --- | --- |
| Repository Baseline（仓库基础版） | 上游派生流程及本仓库实验适配；关闭新增可靠运行时、证据审核与修复 |
| Claim-first（早期方案） | Evidence → 准入 Claim → 报告；早期评测对照 |
| Reliable Deep Research | 面向问题的报告生成、语义审核与有界修复 |

仓库基础版沿用上游研究流程，保留本仓库在检索、模型接入及预算控制方面的实验适配，关闭新增可靠运行时、证据审核与修复。它不是未经修改的官方 Open Deep Research 版本，此比较不能代表对官方原版的性能比较。

## 结果

| 指标 | Repository Baseline（仓库基础版） | Claim-first（早期方案） | Reliable Deep Research |
| --- | ---: | ---: | ---: |
| 验收通过 / 槽位 | 52/60 | 51/60 | **59/60** |
| 降级待复核 | 0 | 0 | **0** |
| 失败或超限 | 8 | 9 | **1** |
| 全部尝试要点覆盖 | 135/168 = 80.4% | 109/168 = 64.9% | **149/168 = 88.7%** |
| 成功报告条件覆盖 | 135/145 = 93.1% | 109/144 = 75.7% | **149/165 = 90.3%** |
| 抽样引用支持 | 123/202 = 60.9% | 244/254 = 96.1% | **219/234 = 93.6%** |
| 平均耗时（秒，含失败） | 404.9 | 667.6 | **319.3** |
| 平均模型调用（含失败） | 9.52 | 19.42 | **15.25** |
| 平均检索调用（含失败） | 1.95 | 3.72 | 2.50 |
| 观测输出 token 总数 | 517,433 | 1,016,755 | 514,544 |

每组全部 60 个展示槽位均进入覆盖率分母，失败贡献零个覆盖要点。质量分子只统计验收通过报告。引用支持每份报告最多抽样 5 条陈述；仓库基础版有 3 份通过报告没有可提取引用。不同系统的验收约定不同，验收率本身不是语义质量分。两次运行归属于同一组 30 道问题，不是 60 道独立问题。

## 统计口径与数据核查

结果按开发阶段保存的评估记录汇总，包含不同配置及已用于故障改进的样本，不代表发布配置的独立全量验证。平均耗时和调用量只统计表内记录，不包含开发过程的其他尝试或外部评审费用。

[发布数据](../benchmarks/results/release_comparison.json)保留全部 180 个比较槽位，每条记录通过 `source_run_id`、`source_profile` 和 `source_experiment` 标明来源。对应的[评分记录](../benchmarks/results/coverage_formal_20261021/model_audit_numeric.json)和[反馈修复评测记录](../benchmarks/results/coverage_retry_20261021/model_audit_numeric.json)用于逐项核查。

```bash
uv run --frozen python -m experiments.evaluation.verify_release_results
```

离线核查检查槽位完整性、来源哈希、逐条记录映射、失败记录保留和汇总指标，不能验证模型语义判断是否正确。

## 修复配置的依据

原始覆盖流程可能删除无支持内容后仍返回需要复核的报告。修复配置使用当前段落审核与当前证据，避免重插旧计划中已否定的答案；保留已核实文本，修正引用绑定后再次审核，最多 2 轮修复、总共 2 个补搜任务。补搜可使用剩余第 4 次检索，同时预留模型和时间预算。研究单元总分配从 3 增至 4，全局任务尝试上限仍为 6。JSON/schema 错误允许 1 次计入预算的格式重试，验收阈值没有放宽。

反馈修复阶段，5 份报告使用修复后复核，另 7 份直接通过。通过可靠性验收的 12 份报告中，外部评审认定 8 份覆盖全部参考要点；内部检查标记 11 份完整、1 份 `incomplete_evidence`。可靠性验收、内部完整性与外部答案覆盖是不同指标，不能将验收变化单独归因于内容修复。

## 数据、模型与预算

- 30 道整理问题：智能体系统 8 道、AI 应用 8 道、软件工程 8 道、CAD 生成 6 道；8 道需要跨文档信息，5 道故意设置为不可回答。
- 24 份文档；分块长度 1,200 字符、重叠 200 字符；BM25 + BGE-small-en-v1.5 倒数排名融合；每次检索最多 5 个块。
- 参考要点由助手编写，并对照文档做机械检查。生成仅接收问题文本。6 道 CAD 问题沿用早期工作，8 道问题曾用于开发诊断，因此不是未见测试集。
- 网关别名 `gpt-6.1-sol`、low 推理强度、流式输出，实际托管模型实现未经独立核实。快速运行默认使用不同的 OpenAI 模型及网络检索。
- 每题全局上限保持 40 次模型调用、4 次检索、6 次任务尝试、1,200 秒、250,000 个估算输入 token、120,000 个观测输出 token。单次输出上限：研究 2,048、压缩 3,072、报告 4,096、摘要 2,048。研究并发 2，任务超时 480 秒。
- 不同开发阶段分别使用 18 个和 6 个报告进程。共享 API 负载与配置变化影响耗时。调用和 token 是成本代理，不是货币金额。

## 评分与来源

仓库基础版和 Claim-first 是保存的历史对照报告，与原始覆盖报告在同一修正协议下重新评分，没有重新生成。各阶段采用相同的严格匿名准则与来源提取。最多 5 条引用陈述按稳定哈希选取，提供所有已解析的被引来源：每个来源使用精确块或词面最接近的两个块，每块 1,400 字符。参考文献解析支持列表前缀，拒绝缺失、额外或重复评分 ID。反馈修复阶段的评审将长 claim ID 双射映射到短 ID，再还原。

仓库基础版有一次评审在计划的两轮之外，额外进行了两次仅补缺失项的格式恢复；已有陈述、证据、参考和有效判断均保留。[ID 格式补充记录](../benchmarks/coverage_formal_20261021/evaluation_id_format_addendum.json)和[执行补充记录](../benchmarks/coverage_formal_20261021/evaluation_execution_addendum.json)披露了此偏离。

失败记录（`agent_02`，第 2 次）超时，清理了未完成任务的 14 条证据，重试时耗尽研究检索分配。无证据分支在补搜路径之前退出，该问题仍未解决。之后的摘要记录错误通过离线恢复处理；生成与评审结束后增加了一行空值保护，没有再次付费请求。参见[失败记录补充说明](../benchmarks/results/coverage_retry_20261021/failure_record_recovery_addendum.json)和[运行后修复记录](../benchmarks/results/coverage_retry_20261021/postrun_summary_guard_fix.json)。

历史[生成清单](../benchmarks/expanded_20261021/frozen_manifest.json)、[重评清单](../benchmarks/coverage_formal_20261021/frozen_manifest.json)与[修复清单](../benchmarks/coverage_retry_20261021/frozen_manifest.json)标识冻结的实验代码及输入。公开打包晚于这些快照。原始报告、来源片段、数据库和评审解释保留在本地；数值记录支持算术核查，不支持独立事实复核。

同模型评审、助手参考点、开发样本选择、生成随机性、并发变化和缺少独立人工复核均限制解释。不能据此宣称普遍优于上游，也不能隔离修复的因果效果。下一步应独立复核，并以发布配置完成全量新运行，保留失败和资源总开销。
